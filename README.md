# キャラクターAR：iPhoneだけで公開する手順

この試作品はカメラ映像に背景透過PNGを重ねる静的Webサイトです。地面認識や現実空間の追跡をするARではありません。

## 無料と安全の設計

- 管理者はGitHub Freeの個人アカウントを使います。見る人の登録は不要です。
- Public（公開）リポジトリと、GitHub Pages標準のgithub.ioドメインを使用します。有料プラン、独自ドメイン、APIキー、サーバー契約、データベースは不要です。
- このアプリには課金機能、広告、アクセス解析、録画、音声取得、位置情報取得はありません。カメラ映像はブラウザ内で表示し、送信・保存しません。
- QRコードは端末内で生成します。入力URLをQR生成サービスへ送信しません。画像共有は「画像を共有」を押して選んだ相手・アプリにのみ渡します。
- ページと画像の取得にはGitHubへの通信が発生します。GitHub側の通常のアクセスログや通信契約の費用までなくすものではありません。
- コードとアップロードした画像は誰でも閲覧・ダウンロードできます。個人情報・秘密情報・利用権のない画像を置かないでください。
- GitHubの料金・規約は将来変更される可能性があります。無料枠は無制限ではありません。2026年10月27日に公式資料を確認しました。

## ファイル（4個）

同じ階層に次の4ファイルを置きます。ZIPそのものをGitHubへアップロードしないでください。

|ファイル|役割|
|---|---|
|index.html|画面・カメラ・画像操作・QRの保存共有。変更は基本的にこのファイルだけ|
|character.png|差し替えられる仮キャラクター|
|qr.js|無料QR生成ライブラリ。変更せずそのままアップロード|
|README.md|この説明書|

主要機能はブラウザ標準機能で実装しています。QRだけ、qrcode-generator 1.4.4（Kazuhiko Arase、MIT License）を同梱しています。index.htmlが相対パスのscriptタグでqr.jsを読み込みます。CDNへの実行時依存はありません。著作権表示・MIT許諾全文はqr.jsの先頭に保持しています。アップロードや再配布時も削除しないでください。
配布元：https://github.com/kazuhikoarase/qrcode-generator
取得したバージョン：https://cdn.jsdelivr.net/npm/qrcode-generator@1.4.4/qrcode.js

## 1. iPhoneで準備する

1. この回答のZIPをダウンロードし、共有メニューから「ファイルに保存」を選びます。
2. iPhoneの「ファイル」アプリで保存先（通常は「ダウンロード」）を開きます。
3. ZIPをタップして展開します。展開したフォルダ内の上記4ファイルを確認してください。
4. Safariと受信可能なメールアドレスを用意します。GitHubアプリやパソコン、Node.jsのインストールは不要です。

## 2. GitHubの無料アカウントに登録する

1. Safariで https://github.com/signup を開きます。すでにアカウントがあればSign inでログインします。
2. メールアドレス、パスワード、ユーザー名など、画面に求められる項目を入力します。ユーザー名は公開URLにも使われます。
3. 人間であることの確認などを完了します。
4. GitHubから届くメールのコードやリンクでメールアドレスを確認します。
5. プランを選ぶ画面が出たらFreeを選びます。この制作に有料プランやクレジットカードの登録は不要です。Pro、Copilot、Codespaces等は申し込む必要がありません。
6. アカウントのSettings → Password and authenticationから、可能ならパスキー・2段階認証を設定し、復旧方法を保管します。パスワードや復旧コードをリポジトリに載せないでください。

## 3. リポジトリ（ファイル置き場）を作る

1. ログインしたSafariで https://github.com/new を開きます。
2. Repository nameに `character-ar` と入力します。
3. Visibilityは必ずPublicを選びます。無料のGitHub Pagesで使うためです。
4. Add README（READMEの追加）をオンにします。初期ブランチを作るためです。
5. Create repositoryを押します。
6. リポジトリのCode画面が開きます。以後、このページをブックマークしておくと便利です。

GitHubの表示は変更されることがあります。Add fileやSettingsが見えない場合は、画面内の「…」メニューや横に並んだタブを確認します。Safariのページメニューで「デスクトップ用Webサイトを表示」に切り替えると操作できる場合があります。

## 4. ファイルをアップロードする（おすすめ）

1. リポジトリのCode画面でAdd file → Upload filesを押します。
2. choose your filesから「ファイルを選択」または「ブラウズ」を開きます。
3. ZIPから展開したフォルダに進み、index.html、character.png、qr.js、README.mdを選びます。複数選択が難しい場合は1個ずつ繰り返します。
4. 画像は「写真ライブラリ」ではなく「ファイル」から選ぶと、ファイル名とPNG形式を維持しやすくなります。
5. アップロード一覧の名前を確認し、Commit changes欄に「ARサイトを追加」と入力します。
6. mainブランチへ直接保存する選択肢でCommit changesを押します。README.mdは用意済みのものを置き換えます。
7. Code画面に4ファイルが並ぶことを確認します。フォルダの中にさらにindex.htmlがある状態ではなく、リポジトリ直下に置きます。

### ブラウザでindex.htmlを新規作成する場合

1. Add file → Create new fileを開きます。
2. Name your fileに `index.html` と入力します。
3. この回答のHTML全文をコピーし、編集欄に貼り付けます。先頭の `<!doctype html>` から最後の `</html>` まで入れます。コードブロックの囲み記号は貼り付けません。
4. Commit changesを押し、確認画面でもCommit changesを押します。
5. character.pngとqr.jsは前の手順で別途アップロードします。qr.jsがなくてもカメラと画像操作は動きますが、QR生成はエラー案内になります。

## 5. GitHub Pagesで公開する

1. リポジトリのSettingsタブを開きます。個人アカウントのSettingsではなく、character-arリポジトリのSettingsです。
2. 設定メニューからPagesを開きます。狭い画面では設定メニューを展開してください。
3. Build and deploymentのSourceをDeploy from a branchにします。
4. Branchをmain、フォルダを/(root)にしてSaveを押します。
5. 数分待ち、同じPages設定画面を再読み込みします。状況によっては10分ほどかかります。
6. Your site is live at…などの表示にあるリンク、またはVisit siteを開きます。**ここに表示されたURLが実際の公開URLです。**
7. Enforce HTTPSが選べる場合はオンにします。標準github.ioドメインはHTTPSに対応しています。
8. Safariのアドレスがhttps://で始まること、キャラクターARの画面が開くことを確認します。

カメラにはHTTPSが必要です。GitHubのファイル閲覧画面、Raw画面、iPhoneのファイルアプリのHTMLプレビューではなく、Pagesの公開URLを使ってください。ローカル開発のlocalhost例外はありますが、iPhone利用者はHTTPSで公開してください。
この納品時点ではGitHubアカウントへのアップロードや公開を行っていません。存在しない公開URLやQRコードは作成していません。

## 6. カメラを使う・許可をやり直す

1. 公開URLをSafariで開き、「カメラを起動」を押します。
2. 許可の確認が出たら「許可」を選びます。マイクへの許可は求めません。
3. 背面カメラが優先されますが、端末・ブラウザによって選ばれるカメラは異なる場合があります。
4. キャラクター自体を1本の指でドラッグします。「大きく」「小さく」「位置を戻す」で調整できます。
5. 「カメラ停止」でストリームを停止します。再度起動できます。タブを離れる・画面を閉じるときにも停止処理を実行します。戻ったら起動を押してください。

拒否してしまった場合：Safariのアドレス欄近くのページメニュー（バージョンによって「ぁあ」等）→Webサイトの設定→カメラを「確認」または「許可」に変更して、ページを再読み込みします。設定項目が見つからない場合は、iPhoneの「設定」→「アプリ」→「Safari」→「カメラ」を確認します。旧iOSでは「設定」→「Safari」です。基本は「確認」を選び、このサイトを開いて許可します。スクリーンタイムや管理端末の制限がある場合は管理者の設定も関係します。

## 7. QRコードを作成・保存・共有する

1. 公開したページをSafariで開き、正常に表示されることを確認します。
2. 下の「公開したページのQRコードを作る」を開きます。
3. 実際の公開URLを貼り付けます。公開ページで操作している場合は「このページのURLを入力」も使えます。このボタンは検索パラメーターと#以降を含めません。
4. 「QRコード作成」を押します。HTTPS形式と一部の例示・ローカルURLを検査しますが、URLの存在や安全性そのものは判定しません。
5. QR画像の下に表示されるURLが自分の公開URLと一致していることを確認します。
6. 「PNGを保存」でファイルとして保存します。Safariで保存しづらい場合は、QR画像を長押しして写真やファイルに保存してください。
7. 「画像を共有」でiPhoneの共有画面を開ける場合があります。対応しない場合は保存した画像を「写真」や「ファイル」から共有します。
8. 別のスマートフォンの標準カメラでQRを読み取り、表示されたリンクをタップします。同じiPhoneの画面をそのiPhoneのカメラで読み取ることはできません。
9. リンク先が正しいこと、Safariでカメラを起動できることを確認してから配布してください。

## 8. キャラクター画像の仕様と差し替え

- ファイル名：`character.png`（すべて小文字）
- 形式：本物のPNG。背景はアルファ透過。JPEGの拡張子だけを変えても透過PNGにはなりません。
- 推奨：長辺600〜1200px程度、2MB以下。必須上限ではなく、読み込みを軽くするための目安です。
- 縦横比は自由で、表示時に維持します。周囲の透明余白は少なめにすると操作しやすくなります。
- 同梱の仮画像：600×800px、透明背景、図形で作った緑色のマスコット。

差し替え手順：
1. 新しいPNGを「ファイル」アプリへ保存します。
2. 長押し→名前を変更でcharacter.pngにします。character.png.pngになっていないか確認します。
3. GitHubのCode→Add file→Upload filesで同じ階層へアップロードします。
4. Commit changesを押して保存します。公開されるまで数分待ちます。
5. 公開ページを再読み込みします。古い画像が残る場合は待ってから再読み込みしてください。
6. それでも更新されない場合は、index.html内の `character.src = './character.png';` を `character.src = './character.png?v=2';` に変更して保存します。次回はv=3などにします。これはキャッシュ更新用で、画像名は変えません。

## 9. 公開後に文章やコードを更新する

1. GitHubのCodeでindex.htmlをタップします。
2. 鉛筆アイコン（Edit this file。メニュー内の場合もあります）を押します。
3. 必要な箇所だけを変更します。画面のタイトルならh1タグ内の「キャラクターAR」などを編集します。
4. Commit changes→変更内容の説明→Commit changesで保存します。
5. Pagesの更新を待ち、Safariの公開ページを再読み込みします。
6. URLが変わらなければQRコードの作り直しは不要です。リポジトリ名やユーザー名を変更してURLが変わった場合は作り直します。

## 10. 無料枠と制約

GitHub Freeの公開リポジトリでPagesが利用できます。現時点の公式制限は公開サイト1GB以下、月100GBの帯域のソフト上限、1時間10回のビルドのソフト上限などです。超過時は制限される可能性があります。本試作に有料プランへの自動申込処理はありません。
GitHub Pagesはオンライン事業・商取引を主目的としたサイトや商用SaaSを運営するための無料ホスティングとしての使用は認められていません。この試作をそのような用途へ拡張する場合は規約を確認してください。
スマートフォン本体、インターネット接続料金、既存の契約料金を無料にするものではありません。

## 11. よくあるエラー

|状況|対処|
|---|---|
|404で開かない|公開設定のmain・/(root)、直下のindex.htmlを確認。公開処理を待つ。Pages画面のURLを開く|
|Pagesを設定できない|Publicか、メール確認済みか、mainに保存済みか確認|
|HTTPSが必要と表示される|ファイルのプレビューではなくhttps://のPages公開URLをSafariで開く|
|許可しても映らない|他のカメラ使用アプリを閉じる。Safariで開き直す。スクリーンタイム等の制限を確認|
|許可の確認が出ない|サイトのカメラ許可を「確認」に戻す。以前の許可が有効なら再確認されない場合もある|
|画像エラー|character.pngの名前・階層・形式を確認。大文字小文字は区別される|
|キャラクターの周りが白い|透過されていない画像。アルファ透過PNGに差し替える|
|QR機能を読み込めない|qr.jsをindex.htmlと同じ場所へアップロード|
|QRを読めない|画像を拡大し、周囲の白い余白を切らない。短い公開URLで生成し直す|
|保存や共有ができない|QR画像を長押しして保存し、写真・ファイルから共有|
|画面を戻したらカメラが停止|安全のための仕様。「カメラを起動」を押す|
|更新が反映されない|数分待つ。再読み込み。画像は上記v=2の手順も参照|
